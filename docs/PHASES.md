# PDSChain v2 — 7-Phase Development Plan

PDSChain v2 follows a strict 7-phase engineering plan. Each phase must pass its automated verification and acceptance gate before the next phase begins.

| Phase       | Name                                                            | Status        | Scope Summary                                                                                                                                                                                                                                                                                                                                                                   |
| ----------- | --------------------------------------------------------------- | ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Phase 1** | **Foundation, Architecture & Project Setup**                    | **COMPLETED** | Monorepo setup (`apps/web`, `apps/api`, `packages/contracts`, `prisma/`), strict TypeScript, ESLint, Prettier, NestJS `/api/v1/health` (`live`, `ready`, summary, DTO ping), PostgreSQL 16 + Prisma initial migration, Hardhat + OpenZeppelin smoke contract & local deployment, React + Tailwind shell & service status UI, Playwright E2E smoke tests, and GitHub Actions CI. |
| **Phase 2** | **Identity, Authentication & Role-Based Access Control**        | **PENDING**   | User identity schema, password hashing, JWT/session authentication, RBAC guards (`STATE_ADMIN`, `WAREHOUSE_MANAGER`, `FPS_DEALER`, `AUDITOR`), audit logging, and protected frontend routes.                                                                                                                                                                                    |
| **Phase 3** | **Smart Contracts & On-Chain Custody Anchor**                   | **PENDING**   | Production Solidity contracts for PDS batch registration, warehouse-to-shop custody transfers, EIP-712 / role-based approvals, and distribution proof anchoring.                                                                                                                                                                                                                |
| **Phase 4** | **Core Off-Chain Domain & Supply Chain Registry**               | **PENDING**   | PostgreSQL domain models and CRUD APIs for districts, warehouses, fair price shops (FPS), commodities, and anonymized beneficiary ration entitlements.                                                                                                                                                                                                                          |
| **Phase 5** | **Dispatch, Transit & Custody Handover Workflows**              | **PENDING**   | Commodity batch allocation, dispatch manifest generation, shop receipt confirmation, and synchronized on-chain transaction anchoring.                                                                                                                                                                                                                                           |
| **Phase 6** | **Beneficiary Distribution, Audit Trail & Public Verification** | **PENDING**   | Fair price shop ration issuance recording, entitlement balance reconciliation, discrepancy alerts, and public/auditor verification portal.                                                                                                                                                                                                                                      |
| **Phase 7** | **System Hardening, E2E Verification & Production Readiness**   | **PENDING**   | Full multi-role Playwright E2E workflows, security hardening, performance testing, backup/recovery verification, and deployment runbooks.                                                                                                                                                                                                                                       |
